An AI-powered PDF invoice parser: any layout and language in, a typed invoice out, plus a decision whether the result can be trusted or needs a person. The language model only reads; everything that has to be exact, including that decision, is done by code.

What the numbers say

  • The cheapest model is enough. gpt-4.1-nano passes every check at $0.61 per 1,000 invoices and is also the fastest.
  • Quality comes from the pipeline, not the model. Six models from three vendors land within one field of each other.
  • Reasoning models do not pay off here: same result, up to four times the output tokens, three times slower.
  • No vendor lock-in: a local model, OpenAI and DeepSeek deployments run through the same code.

Why the decision is made by code

On the invoice with a tampered total, one cloud model changed the numbers so that the arithmetic worked out, in two runs out of two, against an explicit instruction. The invoice would have passed as valid. It was stopped because code requires every reported amount to exist in the document: amounts not found in the document text: total 1558.78. The other five models reported the numbers as printed, and the totals check sent the invoice to a person.

Engineering

  • Agent with typed tools and schema-constrained output on Microsoft Agent Framework.
  • 79 automated tests that need no model, covering the agent loop and the HTTP API; CI on every commit.
  • Evaluation harness with safety gates: a document that must go to review may never come back as valid.
  • README explains each design decision by the failure that led to it, and lists what is not built yet.
